# Site shell notes (wave 1, integrator)

Decisions and assumptions made while building the shell, so later waves do not have to rediscover them. Facts only; verified numbers are in `.verify/summary.json`.

## Decisions that differ from, or go beyond, the brief

1. **Pagefind runs from an Astro integration, not from the npm build script.** `src/plugins/build-integration.mjs` hooks `astro:build:done`. Reason: `tools/verify-page.mjs` builds with `astro build --outDir ...`, which would skip anything chained in `package.json`, and `/search/` would then fail its own verification. Every build, whatever starts it, now produces `/pagefind/`.
2. **`staticwebapp.config.json` is copied into the build output by the same integration.** Finding: the deploy workflow uploads `dist/` as the app, and SWA reads the config only from inside the uploaded folder, so the root config has never been applied in production (checked: the live site returns no `X-Frame-Options`/`X-Content-Type-Options`). During the copy, redirects whose target does not exist in the build fall back to `/topics/`, or `/` when no pillar is live. See `docs/REDIRECTS.md`.
3. **Own sitemap endpoint** (`src/pages/sitemap.xml.ts`) instead of `@astrojs/sitemap` (removed). It emits one `sitemap.xml` with `lastmod` from article `updated` dates and from `src/data/site-pages.ts` for static pages. `robots.txt` points at it. The old rename hack in the build script is gone. `Crawl-delay` and the bot blocks were dropped (audit item 21).
4. **noindex is an HTTP header, not a meta tag**, for `/styleguide/`, `/search/`, `/pagefind/*`, `/404.html` (set in `staticwebapp.config.json`). A robots meta tag makes Lighthouse SEO fail `is-crawlable`, and the brief requires >= 90 on those pages; the header gives the same result in production. These pages are also not in the sitemap, and `/styleguide/` is not linked or indexed by Pagefind.
5. **GA4 loads with Consent Mode defaulted to "denied"** (no cookies), only on the production hostnames, and not at all under Global Privacy Control / Do Not Track. There is no consent banner yet (NEEDS_MARKUS #9), so cookie-less is the only setting the privacy policy can describe truthfully for EEA/UK visitors. To change it, edit `src/scripts/site.ts` and `src/pages/privacy.astro` together. The old per-section GA event was removed.
6. **Syntax highlighting is done in a remark plugin** (`src/plugins/remark-code-blocks.mjs`, Shiki `github-light-default` / `github-dark-default`, CSS-variable output) with Astro's built-in highlighter off. That is what makes fence-meta handling and the attached output panel possible. One theme colour is replaced (comment grey `#6e7781` -> `#57606a`) to reach 4.5:1 on the code background. Ligatures are disabled in code.
7. **MDX is not enabled.** No current need; `.md` plus raw HTML covers diagrams and `<details>`. Ask in `INTEGRATOR_REQUESTS.md` if a component is ever required.
8. **Glossary seeded with 29 core terms** (`src/content/glossary/`), definitions written for this site. Without entries `/glossary/` would be an empty page, and writers need stable ids to link to. "Explained in" links appear only when the target article is published. Wave 3 should extend it and check each definition against the article that teaches the term.
9. **`/topics/` and hubs are generated by one route** (`src/pages/[pillar]/index.astro`), only when at least one non-draft article exists. With zero articles (today's production build) there is no `/topics/`, no "Topics" nav item, no footer topics column, and the homepage omits its topic and "recently published" sections.
10. **Homepage, `/start-here/`, hubs** are functional wave-1 versions with real content (how the site works, how to run examples, how to read code-block labels, reading order). Wave 3 replaces hub intros (`hubIntro` in the pillar YAML), adds the three learning paths, and should reconcile each pillar `blurb` with what actually got published (blurbs describe the planned scope).
11. **The homepage hero code sample** is hand-coloured HTML, not pipeline output. It is the same program as the smoke test in `src/page-content/start-here.md`, which `run-code` verifies. Change both together.
12. **OG images are generated** by `tools/make-images.mjs` (sharp): a default card plus one per pillar, 7-13 KB each; `apple-touch-icon.png` and `logo.png` likewise. The 650 KB `og-default.png` is replaced.
13. **Removed:** `src/pages/guides/*` (17), `resources.astro`, `roadmap.astro`, `500.astro` (SWA never served it), `GuideCard`, `ThemeToggle`, `GuideLayout`, `SETUP.md` (its non-AdSense parts moved to README). `/500.html` redirects to `/`.
14. **Tool changes (no check weakened):** `verify-page.mjs` gained `--drafts` and now HTML-decodes `&amp;`/`&#38;` in `href` values before link checking (it previously mis-parsed any URL with two query parameters as a fragment link). `run-code.mjs` is unchanged.

## Assumptions

- Author id is `markus`, taken from the brief's own `NEEDS_MARKUS` naming; name and bio are markers. The optional author photo (NEEDS_MARKUS #3) has no visible marker because it is optional; there is simply no photo slot until one is supplied.
- The footer copyright shows the `NEEDS_MARKUS(#4)` marker on every page. It is outside `<main>`, so it does not fail pages by itself, but it is visible and must be resolved before launch.
- Terms: code samples may be used "in your own learning and your own projects", which carries over the position of the previous Terms page; articles and diagrams are all rights reserved. **The owner should confirm or choose an explicit licence for code samples** (not currently an item in `NEEDS_MARKUS.md`).
- About/Editorial/Privacy state: no advertising now, no affiliate links, no sponsored posts, one author, AI-assisted drafting with author review (pending sign-off, NEEDS_MARKUS #12), "the author intends to apply for Google AdSense" (from the brief).
- Dates display as "18 September 2026" (en-GB, UTC); `og:locale` is `en_GB`. Change in `src/lib/site.ts` / `BaseLayout.astro` if the owner prefers US style.
- The API function's fallback recipient address in `api/contact/index.js` was left untouched and is not shown anywhere on the site.
- No-JavaScript visitors get the light theme, an always-visible wrapped nav, no copy buttons and no search; everything else works.

## Known limits

- The production 404 status, redirects and headers can only be confirmed after a deploy; locally they were checked by reading `dist/staticwebapp.config.json`, and sirv returns 404 for unknown paths.
- Search currently finds only trust pages, start-here and the glossary, because no articles are published.
- Full-page mobile screenshots of very tall pages show a repeated header near the bottom; that is a Chrome capture artefact (the header is not sticky).

## Wave 2 shell fixes (2026-09-18, after the round-1 design reviews of the pilot articles)

1. **Output panels in callouts (light theme).** `.callout .code-block { background: var(--code-bg) }` was redundant (`.code-block` already sets it) and out-specified `.code-output { background: var(--term-bg) }`. The rule is removed and a comment in `global.css` says why it must not come back. The fixture nests a program + output in note, warning, pitfall, dotnet, exercise and solution.
2. **Scroll affordance.** `site.ts` marks every horizontal scroller (`.code-block pre`, `.table-scroll`, `.diagram-scroll`) with `.fade-r` / `.fade-l` while content is hidden beyond that edge (scroll listener + ResizeObserver, reads batched in one rAF). `global.css` turns the class into a `mask-image` edge fade. A mask fades to whatever is behind the box, so there are no per-theme colours and no contrast cost. No JavaScript: no fade, scrolling still works. `.table-scroll` hand-written in `.astro` pages gets the same behaviour.
3. **Table columns on phones.** `rehype-article` puts `data-col="s|m|l"` on every cell from the longest text in its column (<= 40, <= 80, longer). Under 40em: `s` is `nowrap`, `m` has `min-width: 17rem`, `l` 22rem, so a hidden long cell needs about two lines instead of five. Tables written by hand in `.astro` pages have no `data-col` and behave as before.
4. **Reading time** (`src/lib/content.ts`): prose words / 220 wpm + 2 s per non-blank line of each code block, capped at 40 s per block; `text output` panels, SVG and markup count for nothing. Stated in `docs/WRITER_GUIDE.md` section 2 and on `/editorial-policy/`; change all three together.
5. **TOC text.** `Toc.astro` stripped a trailing `#` from heading text to remove the permalink character, but Astro collects heading text before `rehype-article` adds the permalink, so the only thing it ever stripped was a real "C#"/"F#". The strip is gone; ids are unchanged.
6. **Inline code wrapping.** `rehype-article`: inline code of <= 25 characters gets class `nw` (`white-space: nowrap`). Longer code is split at spaces; each token that fits is a no-wrap span, and a longer token gets `<wbr>` after `. _ / \ , ; ( =` and `::`, then between camelCase words. CSS keeps `overflow-wrap: anywhere` only as the last resort, with `word-break: normal; hyphens: none`. Only `<code>` whose sole child is text is touched; raw-HTML `<code>` in Markdown is not.
7. **End of article.** Every article now ends with a "Keep reading" nav (pillar hub, `/topics/`, `/start-here/`, `/glossary/`), after prev/next and related. Cause of the dead ends: each pilot is alone in its pillar (no prev/next) and the pilots share no tags (no related). Related articles were already cross-pillar by tag overlap; that is unchanged. The layout fixture (tag `layout-fixture`) is no longer offered as prev/next/related on real articles in `--drafts` builds; it still appears on draft hub pages.
8. **`verify-page` `figures`** counts `<figure` elements inside `<main>` only (was `<svg` + `<img` + `<figure`, which double-counted and included icons). No check was changed.
9. **Diagrams.** `rehype-article` wraps the `<svg>` of each `figure.diagram` in `<div class="diagram-scroll" tabindex="0" role="group" aria-label>` and writes the viewBox width into `--vbw`. CSS renders the drawing at 0.92 to 1.2 px per viewBox unit (12-unit text is never under 11 px), scrolls it inside the figure when that is wider than the screen, and keeps the caption still. The figure itself no longer has a tabindex. `diagram-narrow` is a no-op. A viewBox <= 360 fits a 390 px phone without scrolling; that number is the writer rule. Fixture: Figure 1 redrawn 360 wide and stacked, Figure 2 is a deliberate 720-wide scroller.
10. **Writer guide**: section 5 (diagrams) rewritten, new section 7 "Phone width (390 px)", tools section renumbered to 8.

Limits: the fade needs JavaScript. Safari/Firefox were not tested (only Chrome via `verify-page`); `mask-image` with the `-webkit-` prefix is supported by all three. The pilot articles' own figures and wide tables still need redrawing/restructuring by their writers.
